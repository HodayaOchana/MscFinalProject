# BookBridge – הצ'אטבוט (מודל 2): תיעוד מימוש, בדיקות ותוצאות

Nov 5, 2026 · @Hodaya · עודכן Nov 8, 2026 (סעיף "עדכון 8.11: לקראת פיילוט")

## תקציר

מודל 2 הוא צ'אטבוט בשפה טבעית, "Ask BookBridge", שבנוי כ-**LLM עם RAG מבוסס כלים** על Claude API. הוא גם מוצא ספרים וגם מאפשר לקורא להפעיל את האתר מתוך השיחה.

**שלושה עקרונות מובילים את התכנון:**

1. **עיגון:** Claude לא ממליץ מהזיכרון שלו. כל ספר שהוא מזכיר הגיע מכלי שחיפש בקטלוג, והשרת בודק את זה אחרי כל תשובה.
2. **אישור ידני:** המודל לא יכול לשנות נתונים. הוא מציע, ורק לחיצה של הקורא מבצעת את השינוי. מ-8.11 יש לפני האישור גם שומר סף: מודל נפרד שרואה רק את מה שהקורא כתב.
3. **מדידה:** כל שינוי נבדק במספרים. כמה רעיונות נדחו או תוקנו בעקבות המדידה (סעיף "ניסויים ותיקונים").

**מה נבנה:**

- שיחה מרובת סבבים עם חידוד, היסטוריה שמורה והזרמת תשובות.
- 16 כלים: חיפוש, השוואת ספרים, פרטי ספר, ספריות, המלצות ממודל 1, המדף, ניתוח הקריאה, ביקורות, סדרות ופעולות.
- הפעלת האתר מהצ'אט: דירוג, רשימת קריאה, ביקורות, דיון, ז'אנרים ועיר. הכול באישור.
- זיכרון העדפות בין שיחות, גלוי לקורא וניתן למחיקה.
- שילוב דו-כיווני עם מודל 1.

## ארכיטקטורה

```
דפדפן (/chat, ChatBox)
   │  POST /api/chat  { message, conversationId?, location?, bookId? }   (SSE: status / books / delta / done)
   ▼
server/chat.js ── טוען את השיחה מ-DB, מוסיף הקשר (תאריך, עיר, מיקום), זיכרון ונתוני הספר הנשאל
   │
   │  לולאת כלים (עד 8 סבבים):  Claude ──tool_use──► server/chat-tools.js ──► Postgres + pgvector
   │                                ◄──tool_result──                        └─► מודל 1 (recommendFor)
   ▼
עיגון: כל [[book:ID]] נבדק מול הספרים שהכלים החזירו בשיחה; ספר אחר נמחק ונספר
   │
   ▼
קיצורים: הקוד (לא המודל) בוחר כוכבים, ביקורת והוספה ל-TBR מתחת לתשובה
   │
   ▼
שמירה (טרנזקציה): chat_messages (ההיסטוריה ל-API), chat_turns (שורה לכל סבב – להערכה)
   │
   ▼
תשובה: טקסט + כרטיסים + מפה + שאלות המשך + אישורים וקיצורים
                    │
                    └── לחיצה של הקורא ──► ה-API הרגיל של האתר (/api/me/..., /api/social/...)
```

**למה כלים ולא RAG קלאסי:** "כמו X", "מה לקרוא הבא" ו"מה יש לידי" צריכות שליפות שונות. עם כלים, Claude מחליט מה לחפש, והנתונים עדיין מגיעים מהקטלוג.

| `find_book` | שם ספר → מזהים |

### עיגון: אפס ספרים מומצאים

1. Claude כותב כל ספר כסמן `[[book:ID]]`, עם ID מתוצאת כלי.
2. `ground()` בודק כל ID מול הספרים שהכלים החזירו. ספר לא מוכר נמחק ונספר ב-`ungrounded`, ואם הוא פותח שורת רשימה נמחקת כל השורה.
3. `tidyTitles()` מוחק שם ספר שנכתב ליד הסמן.
4. המספר נשמר ב-`chat_turns.ungrounded`.

**מה העיגון לא בודק:** הוא מוודא שהספר קיים, אבל לא שכל טענה על הספר נכונה. במסך אמיתי ראינו את הבוט מתקן בעצמו טענה על מרחק של סניף שהוא "never checked". את זה מודדת מ-8.11 בדיקת הנאמנות (סעיף "עדכון 8.11").

## הפעלת האתר מהצ'אט

המטרה: גם מי שלא מכיר את האתר יוכל להפעיל אותו דרך הצ'אט. המיקוד הוא בקוראים, שהם רוב המשתמשים.

| תחום | פעולה | איך זה עובד בצ'אט |

**נשאר בקישור בלבד:** הרשמה, התחברות, יציאה, הסכמות ופרטיות, בקשה להיות סופר, העלאת ספר, הצמדת פוסט, אישור מו"ל, ניהול ומחיקת חשבון. אלה החלטות משפטיות ואבטחה או טפסים מלאים. מסכי הסופר נשארו מחוץ לצ'אט בהחלטה מכוונת.

### אישור ידני

**האיום:** prompt injection. המודל קורא טקסט שכתבו אחרים (תיאורי ספרים, ביקורות, פוסטים). טקסט כזה יכול לנסות לגרום לו לבצע פעולה, למשל לתת לספר 5 כוכבים. [OWASP](https://docs.unique.ai/security-and-compliance/it-security/owasp-top-10-for-llm-applications-2025) מדגיש את החיבור בין הזרקה לבין הרשאות יתר של המודל.

**הפתרון:** המודל רק מציע. מתחת לתשובה מופיעה שאלה, למשל **Add The Hobbit to your TBR? `Yes, add it` / `Not now`**. השינוי מתבצע רק בלחיצה, דרך ה-API הרגיל של האתר.

- **הבטחה ברמת הקוד:** גם מודל שהוטעה לא יכול לשנות נתונים.
- **המחיר:** לחיצה נוספת. זו בחירה מכוונת של אבטחה על פני נוחות.
- **ניסוח:** הבוט כותב "just confirm below" ולא "אני לא יכול".
- **שומר סף (מומש 8.11):** לפני שהאישור מופיע, מודל נפרד שרואה רק את מה שהקורא כתב משאיר רק את הפעולות שהוא ביקש. הלחיצה נשארת. ביצוע מיידי בלי לחיצה **לא מומש**. ראו `docs/BookBridge – רעיון להמשך שומר סף לפעולות בצ'אט.md` וסעיף "עדכון 8.11".

### קיצורים מתחת לתשובה

הקיצורים נבחרים בקוד ולא בידי המודל, ולכן הם נשארים מעטים וטקסט בתיאור ספר לא יכול להשפיע עליהם. הלחיצה היא האישור.

| קיצור | מתי | הגבלה |
| --- | --- | --- |
| `+` הוספה ל-TBR | הספרים שהתשובה מציעה, בלי ספרים שדורגו, נקראו, הוסתרו או כבר ברשימה | עד 3 |
| "Already read X?" ★★★★★ | הספר שהקורא שאל עליו או השווה אליו | פעם בשיחה, 3 ביום, ספר פעם אחת בלבד |
| `Add a review` | אחרי דירוג, או על ספר שכבר דורג | אותה הגבלה |

**למה לא מבקשים לדרג ספר שהבוט המליץ עליו:** הקורא עוד לא קרא אותו, ודירוג שלו יכניס רעש למנוע. לכן מציעים דירוג רק לספר שהקורא עצמו הזכיר.

### ביקורות ופוסטים

הטקסט פומבי בשם הקורא, ולכן:

- הבוט מעביר את המילים של הקורא ולא ממציא. גם כשמבקשים ממנו "תמציא", הוא מציע לסדר את מה שהקורא כותב.
- הטקסט מוצג בתצוגה מקדימה שאפשר לערוך, ורק לחיצה מפרסמת.
- ביקורת דורשת דירוג, כמו באתר. אם צוינו כוכבים, הם נשמרים ביחד עם הביקורת.

### דירוג אחיד בכל האתר

ספר שדורג נשאר מוצג עם הכוכבים ואפשר לשנות את הדירוג: ב-For You, בצ'אט, בעמוד הספר וב-Rate more. אחרי רענון של For You הספר לא יופיע שם, כי המנוע לא ממליץ על ספרים שכבר דורגו. הוא נשאר ב-My shelf ובעמוד הספר.

### התחלה למשתמש חדש

צ'אט חדש מציג תפריט כפתורים (Find a book, My reading, The site), ומעליו, כשיש, הצעות אישיות לפי מה שהקורא עשה לאחרונה (סעיף "עדכון 8.11"), והבוט מכיר את עמודי האתר ומקשר אליהם. רק קישור פנימי הופך ללחיץ. קישור לאתר חיצוני בתשובה לא נהיה קישור.

### כפתור "Ask" על ספר

הכפתור פותח צ'אט חדש עם הספר מסומן. **שום שאלה לא נשלחת לבד.** הקורא כותב שאלה, או בוחר הצעה שנכנסת לשדה הכתיבה ואפשר לערוך אותה לפני השליחה.

## זיכרון בין שיחות

- **מה נשמר:** העדפות קריאה קבועות שהקורא אמר בעצמו ("I hate horror"). לא בקשה חד-פעמית, ולא פרטים אישיים.
- **אישור:** כמו כל פעולה, ההעדפה נשמרת רק אחרי לחיצה.
- **שינוי דעה:** העדפה חדשה מחליפה את הקודמת, והאישור מציג מה מוחלף.
- **שקיפות:** הרשימה מוצגת תחת "What I remember", ואפשר למחוק כל פריט. מדיניות הפרטיות עודכנה.
- **שימוש:** ההעדפות מצורפות לתחילת שיחה חדשה כמידע, ולא כהנחיה. בבדיקה, בשיחה חדשה החיפוש הוציא אימה לבד והגביל ל-300 עמודים.
- **מה זה לא עושה:** ההעדפה לא מגיעה למנוע של מודל 1, ולא משנה את For You. כשהבוט קורא למנוע, הוא יכול רק לסנן את התוצאות.

## השילוב עם מודל 1

| כיוון | מה | איפה |
| --- | --- | --- |
| צ'אט → מודל 1 | `recommend_for_me` קורא לאותה פונקציה של For You | `server/me-routes.js` |
| מודל 1 → כרטיסים | אחוז התאמה יחסי והסבר במילים של הקורא | `server/match.js`, `server/explain.js` |
| צ'אט → אות למודל 1 | לחיצה על "Ask" נספרת: משקל 3, ועוד 0.5 על כל לחיצה, עד 4. בין "ב-TBR" (1) ל"פתח תוצאת חיפוש" (3.5) | `CF/signal-weights.js`, `me-routes.js`, `CF/retrain.js` |

- **ביקורות ופוסטים לא נכנסים למנוע.** הן מעשירות את האתר, אבל את ההמלצות משפרים בעיקר הדירוגים.
- **שיפור המנוע לא נמדד.** בלי משתמשים אמיתיים אפשר רק לספור כמה דירוגים מגיעים מהצ'אט.
- **ההצעה מתארת REST,** ואצלנו זו קריאה בתוך אותו שרת. ההתנהגות זהה, ובהפרדת שירותים `recommendFor` מוחלף בקריאת HTTP.

## חיפוש (RAG)

המדידה: `server/eval-search.js`, 40 שאילתות עם תשובה ידועה, בלי Claude ובחינם. 20 מתארות ספר במילים אחרות, ו-20 הן מונח מדויק (דמות, מקום).

## ניסויים ותיקונים

התקלות האלה נמצאו בבדיקות, וחלקן נבעו מטעויות שלנו. הן מתועדות כי הן הסיבה לחלק מההחלטות.

3. **תשובה ריקה (Sonnet):** לפעמים חוזר רק בלוק thinking עם `stop_reason: "tool_use"`. הקוד שלח הודעה ריקה וקיבל שגיאה 400, וזה הפיל 2 מתוך 50 שיחות. עכשיו התשובה נזרקת והסבב נשאל שוב. המקרה עדיין קורה, והסיבה לא ידועה.
4. **"just confirm below" בלי אישור (Haiku):** בבדיקת ההוספה לרשימה זה קרה ב-5 מתוך 6 ריצות, והקורא לא היה רואה אישור. הקוד מחזיר את המודל לבצע את זה, במחיר סבב נוסף.
5. **הרצות מזוהמות (טעות שלנו):** עצירת ריצה באמצע השאירה הערת זיכרון על קורא הבדיקה, וזו השפיעה על הריצות הבאות ועל 50 השיחות ("I know you've said horror isn't usually your thing"). הכול נזרק והורץ מחדש. עכשיו ריצה לא מתחילה אם לקורא הבדיקה יש הערות שמורות.

**מה שונה:**
- "כמו X" ו-"X או Y?" בסבב כלים אחד: `search_books` ו-`compare_books` מקבלים שמות ספרים, בלי `find_book` לפני.
- ההנחיות מבקשות לקרוא לכלים בלתי תלויים באותו סבב.
- בזמן ההמתנה כתוב מה נמצא: "Found 6 books – picking the best ones for you…".
- נשמרים `first_text_ms` (מתי הופיעו המילים הראשונות של התשובה) ו-`rounds`.

**תוצאה בהערכה האוטומטית (Haiku):** 2.18 סבבים בממוצע לתשובה. חציון 5.2 שניות, p95 7.6 (לפני: 5.3 / 8.2).

**מה לא שונה:** הורדת ה-effort לפי סוג ההודעה. שינוי effort באמצע שיחה מבטל את המטמון, וסבב בלי כלים כבר לוקח כ-2.5 שניות. גם ניתוב בין Haiku ל-Sonnet לא מומש: בלוקי ה-thinking קשורים למודל, וההערכה משווה בין המודלים.

### חוויה
- **הסבר אישי:** לכל תוצאה של `search_books` ו-`compare_books` מחושב הספר שהקורא אהב (4–5 כוכבים) הכי קרוב אליו בתוכן, אם הדמיון לפחות 0.5 (cosine של ה-embeddings). הסף נבחר במדידה על הקורא הפעיל ביותר: 0.56 ל-*Queen of Babble* ← *Bridget Jones's Diary*, ו-0.36 לזוגות לא קשורים. הבוט משתמש בזה בתשובה, והכרטיס מציג "Close to X, which you loved".
- **פתיחה אישית (`GET /api/chat/start`):** שיחה חדשה מציעה לפי מה שהקורא עשה לאחרונה: ספר שסיים, ספר שדירג 5, ספר על השידה, הסימנייה הוותיקה. קריאה בלבד.
- **השוואה:** `compare_books` מחזיר עמודים, שנה, דירוג קוראים, תגיות, "קרוב לספר שאהבת" וזמינות בעיר. הדף מציג טבלה, והתשובה עצמה 2–4 משפטים. נשמר ב-`chat_turns.comparison`, ולכן מופיע גם בשיחה ישנה.
- **שאלות הבהרה:** רק כשאין במה לחפש, ולעולם לא יותר משאלה אחת. **נמצא בבדיקה:** הדוגמה בהנחיות עצמה הכילה שתי שאלות ("something gripping…? a long read or a short one?"), והמודל העתיק אותה. תוקן.

### אמינות
- **שומר סף לפעולות (`server/chat-judge.js`):** אחרי התשובה ולפני שהאישורים מוצגים, Haiku ב-effort נמוך מקבל רק את ההודעות של הקורא, את שמות הספרים שהוצגו ואת הפעולות המוצעות (סוג ושם, בלי תיאור). הוא מחזיר אילו פעולות התבקשו, והשאר נמחקות ונרשמות. הלחיצה נשארת. אם שומר הסף נכשל, הפעולות נשארות, כי הלחיצה עדיין מגינה. רץ רק כשיש פעולה, ומוסיף כשנייה.
  - `eval-gatekeeper.js`: 8/8. בין המקרים: תיאור זדוני שביקש דירוג, הוספה וזיכרון (הכול נעצר), בקשה אמיתית לאחת מהן (רק היא נשארת), "yes, add the first one", 4 כוכבים שהמודל הפך ל-5 (נעצר), ומשאלה חד-פעמית שהוצעה כהעדפה קבועה (נעצרה).
- **נאמנות לעובדות (`server/eval-faithfulness.js`):** מודל שופט (Sonnet) מפרק כל תשובה לטענות על ספרים ובודק כל אחת מול תוצאות הכלים בשיחה עד אותה תשובה. ב-8 התשובות האחרונות: 69 מתוך 76 טענות נתמכו (91%), ו-5 תשובות היו נאמנות לגמרי.
  - **ממצא:** הבוט העתיק כמעט מילה במילה את התשובה לדוגמה מההנחיות ("reads well on its own"), כי היא השתמשה בדיוק בספרים שהחיפוש מחזיר על Dune. הדוגמה הוחלפה בתבנית בלי ספרים אמיתיים.
  - **ממצא:** פרט מומצא אחד ("narrated by a young chemist").
  - **טעות שלנו במדידה:** בגרסה הראשונה השופט ראה רק את תוצאות הכלים של אותו סבב, ולכן סימן כשגויות עובדות מסבבים קודמים (82%). תוקן.

## מגבלות והשלבים הבאים

- **הערכה אנושית:** עדיין לא בוצעה. אם הממוצע מתחת ל-4, נשתמש בשיחות החלשות ובהערות כדי לשפר.
- **מעריכים:** אם ההצעה מחייבת 3 אנשים שונים, צריך לוודא ששלושת החשבונות שייכים לאנשים שונים.
- **בחירת מודל:** מחכה לציונים. Haiku זול משמעותית. אפשר להריץ `eval-dialogues.js` גם איתו ולהשוות, וזה מכפיל את עבודת המעריכים.
- **נאמנות העובדות:** נמדדת מ-8.11 (91% מהטענות ב-8 תשובות). המדגם קטן, והשופט עצמו יכול לטעות: חלק מה"פספוסים" הם תיאורים גבוליים ("more atmospheric").
- **בדיקת שימושיות:** עדיין לא נעשתה. המטרה "גם מי שלא מכיר את האתר" לא נמדדה על אנשים.
- **משקל האות מהצ'אט (3)** הוא החלטת תכנון, ולא נמדד.
- **הזמינות בספריות מדומה.**
- **בהמשך, לפי סדר עדיפות:** חיפוש לפי תיאור (50% בלבד, סעיף "חיפוש"), עברית, [משתמש מדומה](https://langwatch.ai/docs/agent-simulations/introduction), סט שאילתות נפרד לחיפוש, ביצוע מיידי של פעולות אחרי שומר הסף. מודל שופט, משוב 👍/👎, מסך מדידה ושומר הסף לפני האישור מומשו ב-8.11.

## איך מריצים

```bash
node db/create-chat-tables.js && node db/create-chat-eval-tables.js   # טבלאות, פעם אחת
npm test                                                              # בדיקות יחידה
node server/eval-search.js                                            # החיפוש
CHAT_MODEL=claude-sonnet-5-5 node server/eval-chat.js                 # הערכה אוטומטית (עולה כסף)
CHAT_MODEL=claude-sonnet-5-5 node server/eval-attacks.js              # תקיפות (עולה כסף)
node server/eval-gatekeeper.js                                        # שומר הסף, 8 מקרים (עולה מעט)
node server/eval-faithfulness.js --count 30                           # נאמנות לעובדות (עולה כסף, שופט Sonnet)
node server/eval-from-feedback.js && node server/eval-chat.js --regressions   # ה-👎 של הקוראים (עולה כסף)
CHAT_MODEL=claude-sonnet-5-5 node server/eval-dialogues.js --fresh    # 50 השיחות (עולה כסף)
cd e2e && npm install && npx playwright install chromium && npm test  # דפדפן
```

המעריכים מתווספים ל-`RATER_EMAILS` בקובץ `.env`, ונכנסים ל-`/evaluate`. המשוב מהקוראים (👍/👎, מהירות, "Not for me") ב-`/evaluate/feedback`.

תוצאות שיש בהן הודעות של קוראים אמיתיים (`eval-regressions*`, `eval-faithfulness-*`) נשמרות ב-`logs/`, שלא נכנס ל-git.
